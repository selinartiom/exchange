# EXMONEY — платформа обменника

Сайт с живым калькулятором курсов, публичный API, Telegram Mini App,
панель администратора и Telegram-бот — всё на общей БД PostgreSQL.

## Компоненты

| Компонент | Где | Команда запуска |
|---|---|---|
| Сайт + API + Админка + Mini App | `public/`, `src/` | `npm start` (порт 3000) |
| Telegram-бот | `bot/` | `npm run bot` |
| БД | PostgreSQL, отдельно | см. ниже |

Сайт и бот — разные процессы, оба подключаются к одной PostgreSQL по
`DATABASE_URL`. Заявка, оформленная в одном месте, сразу видна в другом —
никакого кэша в памяти, каждое обращение идёт напрямую в БД.

## Автоподтверждение платежей через блокчейн

> **Что реально проверено, а что нет:** деривация BTC-адресов из xpub сверена
> с официальным тест-вектором BIP32 (математика подтверждена). Логика
> сопоставления TON-платежей по комментарию проверена на смоделированном
> ответе toncenter (реальные сетевые вызовы к toncenter.com и
> blockstream.info недоступны в среде, где это разрабатывалось — сетевые
> ограничения песочницы, а не проблема кода). Перед тем как доверять этому
> реальными деньгами — протестируйте на тестовых суммах на своём сервере,
> где эти API реально доступны.

- **TON** — работает "из коробки", без дополнительной настройки. Клиенту в
  боте показывается инструкция указать код заявки в комментарии к переводу;
  фоновый воркер (`src/blockchainWatcher.js`, тикает раз в 2 минуты) сверяет
  входящие транзакции на `walletTon` через публичный toncenter API и по
  совпадению комментария переводит заявку в `AWAITING_CONFIRMATION`
  автоматически — оператору остаётся только подтвердить выплату.
- **BTC** — включается только если в настройках указан **xpub** (расширенный
  публичный ключ, watch-only — приложение никогда не видит приватный ключ и
  не может тратить средства). С xpub на каждую BTC-заявку выделяется
  уникальный адрес (деривация проверена на официальном тест-векторе BIP32),
  и платёж на него сопоставляется однозначно — в отличие от TON, у BTC нет
  поля для комментария, поэтому без xpub общий кошелёк нельзя надёжно
  привязать к конкретной заявке. **Без xpub BTC подтверждается вручную, как
  и раньше** — это осознанный компромисс в пользу того, чтобы не рисковать
  спутать чужие платежи.
- **USDT/CASA на TON** — вне охвата автоподтверждения. Технически это джеттон
  (не нативный перевод TON), и разбор сообщений джеттон-переводов требует
  отдельной, более сложной логики (либо парсинг BOC, либо API вроде
  tonapi.io с уже декодированными jetton-событиями). Пока подтверждается
  оператором вручную.
- Настраивается в админке → Настройки → «Автоподтверждение платежей»:
  xpub, необязательный TON API key (для более частого опроса без лимитов
  toncenter) и требуемое число подтверждений сети отдельно для BTC и TON.

xpub для BTC экспортируется на уровне account (например, в Electrum: правый
клик по кошельку → «Show public key»; из аппаратного кошелька — account-level
xpub для пути m/84'/0'/0'). Адреса деривируются по пути `xpub/0/index`
(внешняя/receiving цепочка BIP44/BIP84).

## Роли админов, заметки к заявкам, подписка на курс

- **Роли** — вместо одного логина из `.env` теперь таблица `admins` с ролями
  `owner` (полный доступ, включая настройки и управление другими админами) и
  `operator` (только заявки — подтверждение/отклонение/заметки, без
  настроек). При первом запуске, если таблица `admins` пуста, а в `.env`
  заданы `ADMIN_USERNAME`/`ADMIN_PASSWORD_HASH` — автоматически заводится
  владелец из них (не нужно ничего мигрировать руками). Дальше новые
  аккаунты создаются прямо в админке → Настройки → «Админы» (видно только
  владельцу).
- **Внутренние заметки к заявке** — текстовое поле, не видное клиенту,
  доступно и владельцу, и оператору. Открывается там же, где «История»
  заявки в админке.
- **Подписка на курс в боте** — `/alert` заводит подписку (актив →
  направление → целевая цена в MDL), `/myalerts` показывает активные и
  даёт отменить. Фоновый воркер (`src/priceAlertWorker.js`, раз в 5 минут)
  сверяет текущее табло и уведомляет клиента при достижении цены —
  подписка одноразовая, после срабатывания деактивируется.

## Тесты и CI

`npm test` — юнит-тесты на чистую логику, без БД и без сети (быстро и
надёжно в CI): расчёт котировок (`src/rates.js`), деривация BTC-адресов
(сверено с официальным тест-вектором BIP32) и CSRF-мидлвар. GitHub Actions
(`.github/workflows/ci.yml`) гоняет их при каждом пуше и PR — плюс
синтаксическая проверка всех `.js` файлов.

## Деплой через Docker Compose

```bash
cp .env.example .env
# заполните .env как обычно + POSTGRES_USER/POSTGRES_PASSWORD/POSTGRES_DB
docker compose up -d --build
```

Поднимает три контейнера: `db` (PostgreSQL 16, схема применяется
автоматически при первом старте пустого volume), `app` (сайт+API+админка,
порт из `PORT` в `.env`, по умолчанию 3000) и `bot`. Все три общаются между
собой по внутренней docker-сети — `DATABASE_URL` для `app`/`bot` собирается
из `POSTGRES_*` автоматически и указывает на `db`, а не на `localhost`
(даже если в `.env` записано другое — compose переопределяет).

Дальше: логи — `docker compose logs -f app`, обновление после изменений в
коде — `docker compose up -d --build`, снести всё вместе с БД — `docker
compose down -v` (без `-v` volume с данными останется).

## Что нового: авто-протухание, журнал событий, статистика

- **Авто-протухание заявок** — если клиент не оплатил в течение `quoteTtlMinutes`,
  заявка сама переходит в статус `EXPIRED` (проверка раз в минуту, см.
  `src/expiryWorker.js`, запускается вместе с `npm start`). Клиенту, если он
  известен, уходит уведомление в Telegram.
- **Журнал событий по заявке** (таблица `order_events`) — кто и когда создал,
  оплатил, подтвердил или отклонил заявку. Смотреть — кнопка «История» у
  каждой заявки в админке.
- **Уведомление админов о новой заявке с сайта** — не только когда клиент
  нажал «Я оплатил» в боте, но сразу при оформлении на сайте.
- **Графики в дашборде** — заявки и объём по дням за последние 14 дней.

## Безопасность, дубли, экспорт, мультиязычность

- **Rate limiting** (`express-rate-limit`) — курсы/котировка: 60 запросов/мин;
  создание заявки: 5 за 10 минут с IP; логин в админку и Telegram-auth:
  10 попыток за 15 минут.
- **Helmet** — стандартные security-заголовки (X-Frame-Options, HSTS и т.д.).
  CSP отключён намеренно — сайт использует инлайн-скрипты.
- **CSRF-защита** — токен на сессию (`GET /api/csrf-token`), обязателен в
  заголовке `X-CSRF-Token` для создания заявки, подтверждения/отклонения в
  админке, сохранения настроек, logout. Фронтенд уже подключён везде.
- **Защита от дублей** — если один клиент (по telegramId или контакту)
  отправляет идентичную заявку в течение 15 секунд, отдаём уже созданную
  вместо новой. Работает на сайте и в боте (двойной тап по кнопке).
- **Экспорт заявок в CSV** — кнопка «⬇ CSV» на вкладке «Заявки» в админке,
  учитывает текущие фильтры, с BOM для корректной кириллицы в Excel.
- **RU/RO на сайте** — переключатель в шапке
  (`public/index.html`), выбор языка сохраняется в
  `localStorage`. Админка пока только на русском.

Если сервер стоит за nginx/Caddy — включите `TRUST_PROXY=true` в `.env`,
иначе rate limiting будет считать все запросы с одного IP (адреса прокси),
а не с реальных клиентов.

## 1. Поднимаем PostgreSQL

Можно на том же сервере, что и приложение, или на отдельном — код одинаковый,
меняется только адрес в `DATABASE_URL`.

**Ubuntu 24.04 LTS** (рекомендую — стабильнее для БД, чем свежая 26.04):

```bash
sudo apt update
sudo apt install -y postgresql postgresql-contrib
sudo systemctl enable --now postgresql

sudo -u postgres psql -c "CREATE USER nexchange WITH PASSWORD 'придумайте-пароль';"
sudo -u postgres psql -c "CREATE DATABASE nexchange OWNER nexchange;"

# Применяем схему (таблицы orders и settings)
PGPASSWORD=придумайте-пароль psql -h localhost -U nexchange -d nexchange -f db/schema.sql
```

Если БД на **отдельном сервере** — там же выполняете установку и `CREATE
USER/DATABASE`, а в `postgresql.conf` разрешаете внешние подключения
(`listen_addresses = '*'`) и в `pg_hba.conf` добавляете правило для IP
сервера приложения. Дальше в `.env` приложения указываете внешний адрес БД,
не `localhost`.

## 2. Устанавливаем и настраиваем приложение

```bash
npm install
cp .env.example .env
```

Заполните `.env`:
- `DATABASE_URL` — строка подключения к БД из шага 1
- `SESSION_SECRET` — любая случайная строка
- `TRUST_PROXY` — `true`, если сервер стоит за nginx/Caddy (нужно для корректной работы rate limiting)
- `ADMIN_USERNAME` / `ADMIN_PASSWORD_HASH` — хэш получить командой:
  ```bash
  npm run hash-password -- "ваш-пароль"
  ```
- `BOT_TOKEN` — токен от @BotFather
- `ADMIN_IDS` — ваш Telegram user_id (узнать у @userinfobot)
- `BOT_USERNAME` — юзернейм бота без @

Реквизиты карты/кошельков и лимиты — их проще один раз выставить прямо в
`db/schema.sql` перед первым запуском (секция `INSERT INTO settings`,
значения по умолчанию в `CREATE TABLE settings`), а дальше менять в админке
(`/admin` → Настройки), без правки кода и без рестарта.

## 3. Telegram Mini App

Mini App открывает основной калькулятор внутри Telegram, проверяет `initData`
и привязывает заявку к Telegram ID клиента. В BotFather настройте Main App и
Menu Button на `MINI_APP_URL`, например `https://app.exmoney.online/?tg=1`.

Локально (`localhost`) виджет Telegram не работает в принципе — тестировать
вход можно только на реальном домене с HTTPS.

## 4. Запуск

```bash
npm start      # сайт + API + админка + Mini App → http://localhost:3000, админка → /admin
npm run bot    # телеграм-бот, отдельным процессом/терминалом
```

Для продакшена — оба процесса под pm2 или systemd, плюс nginx/Caddy с TLS
перед сайтом (Telegram Mini App требует HTTPS).

## Что нужно доделать перед реальным запуском

1. **Юридическая часть** — регистрация деятельности, AML-политика,
   консультация с юристом по CASP-регулированию (см. более раннее
   обсуждение про обменники в Молдове).
2. **Банковский счёт для приёма MDL** — сейчас реквизиты статичные,
   для масштаба понадобится эквайринг или бизнес-счёт.
3. **Домен + HTTPS** — обязателен для Telegram Mini App и secure-cookie.
4. **USDT/CASA на TON** — авто-подтверждение не реализовано (см. раздел выше),
   подтверждается оператором вручную. BTC и TON — автоматически, если
   настроены (xpub для BTC, из коробки для TON).
5. **KYC-модуль** — сейчас только текстовое предупреждение о лимите; нужен
   реальный сбор документов при превышении суммы.
6. **Курс USD/MDL** — берётся с публичного бесплатного API
   (exchangerate.host). Для официальной точности лучше ориентироваться на
   курс НБМ (bnm.md).
7. **Бэкапы БД** — `pg_dump` по расписанию, это единственное место, где
   живут все заявки и настройки.
8. **Смена пароля админки** — обязательно сгенерируйте новый хэш перед
   реальным запуском, не используйте значение из примера.

  admin/

  server.js               — Express-сервер, точка входа npm start
  db.js                    — доступ к PostgreSQL (orders, order_events, settings)
  expiryWorker.js           — фоновая проверка просроченных заявок
  blockchainWatcher.js       — фоновая проверка блокчейна (BTC/TON автоподтверждение)
  blockchain/

  middleware/
    auth.js                    — проверка сессии администратора + requireOwner
    clientAuth.js                — проверка клиентской Telegram-сессии
    csrf.js                        — CSRF-токен на сессию
    rateLimit.js                    — лимиты частоты запросов
  routes/
    api.js                       — публичный API (курсы, котировка, заявки)
    admin.js                      — защищённые маршруты админки (роли, заметки, история, графики)
    client.js                      — Telegram-auth для Mini App, заявки клиента
